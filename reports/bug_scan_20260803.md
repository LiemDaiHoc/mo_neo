### BUG-001 🔴 CRITICAL — Turn không advance sau `handleDiscardPickerPick`

**File:** `server/ServerGame.js`  
**Dòng:** 1171–1207  

**Root cause:**  
Sau khi người chơi chọn thành công 1 lá từ discard pile (combo 5 lá), hàm kết thúc bằng:
```js
this.pendingAction = null;
this.broadcastState();
// THIẾU: không gọi startTurn() hoặc advanceToNextPlayer()
```

**Trigger:** Bất kỳ khi nào combo 5 lá thành công và discard pile có bài.

**Impact:** 🔥 Game bị **đóng băng vĩnh viễn** — không ai có thể hành động, server không crash nhưng game state bị treo. Người chơi phải reload và reconnect.

**Fix direction:**  
Sau `this.broadcastState()` ở L1206, thêm:
```js
const player = this.players.find(p => p.id === playerId);
player.turnsToPlay--;
if (player.turnsToPlay <= 0) {
  player.turnsToPlay = 1;
  this.advanceToNextPlayer();
} else {
  this.startTurn();
}
```

### BUG-002 🔴 CRITICAL — `resolveFiveCardCombo` không advance turn khi discard trống

**File:** `server/ServerGame.js`  
**Dòng:** 1141–1145  

**Root cause:**
```js
if (this.discardPile.length === 0) {
  this.addLog(`✨ ${player.name} chơi Combo 5 lá nhưng xấp bài bỏ đang trống!`);
  this.broadcastState();
  return; // ← không advance turn
}
```

**Trigger:** Người chơi đánh combo 5 lá khi discard pile trống (đầu game, hoặc sau khi shuffle clean).

**Impact:** 🔥 Game **đóng băng** — người chơi bị kẹt, không thể rút bài hay đánh bài (vì không phải pending action, nhưng cũng không có turn_start).

**Fix direction:**
```js
if (this.discardPile.length === 0) {
  this.addLog(`...`);
  // Advance turn như bình thường
  player.turnsToPlay--;
  if (player.turnsToPlay <= 0) {
    player.turnsToPlay = 1;
    this.advanceToNextPlayer();
  } else {
    this.startTurn();
  }
  return;
}
```

### BUG-003 🔴 HIGH — `ekCard` bị mất khi disconnect trong lúc defuse

**File:** `server/ServerGame.js`  
**Dòng:** 1261–1265  

**Root cause:**
```js
if (this.pendingAction.type === 'defuse' && this.pendingAction.playerId === socketId) {
  this.pendingAction = null; // ← ekCard trong pendingAction.ekCard bị hủy
}
```
Lá Mèo Nổ (ekCard) đang được giữ trong `pendingAction.ekCard` — khi null hóa pendingAction, ekCard không được đưa vào deck hay discardPile. **Lá Mèo Nổ biến mất khỏi game**.

**Trigger:** Người rút Mèo Nổ có Defuse → mất kết nối trong lúc đang chọn vị trí đặt EK.

**Impact:** Số lá Mèo Nổ trong game giảm 1 → game có thể kết thúc mà không đủ EK để loại hết người chơi (cân bằng game bị phá vỡ).

**Fix direction:**
```js
if (this.pendingAction.type === 'defuse' && this.pendingAction.playerId === socketId) {
  // Đặt EK vào vị trí ngẫu nhiên trong deck thay vì mất đi
  const ekCard = this.pendingAction.ekCard;
  const randomPos = Math.floor(Math.random() * (this.deck.length + 1));
  this.deck.splice(randomPos, 0, ekCard);
  this.pendingAction = null;
}
```

### BUG-004 🔴 HIGH — Reconnect vào game đang playing → màn hình trắng

**File:** `public/js/network.js`  
**Dòng:** 145–151  

**Root cause:**
```js
if (data.room && data.room.status === 'playing') {
  UI.showGame();
  Game.initOnline(); // ← không truyền serverData!
}
```
`Game.initOnline()` gọi mà không có tham số. Trong `game.js`, `initOnline(serverData)` nếu `serverData` là `undefined` thì không gọi `updateFromServer()` → game state trống.

**Trigger:** Người chơi mất kết nối và reconnect thành công khi game đang chạy.

**Impact:** Client hiển thị màn hình game nhưng không có bài, không thấy đối thủ, không thể hành động. Cần server push state mới sau reconnect.

**Fix direction:**
Sau reconnect thành công trong RoomManager, gọi:
```js
if (room.game) {
  room.game.handlePlayerReconnect(oldSocketId, socket.id);
  // handlePlayerReconnect đã gọi broadcastState() → server sẽ gửi game_state
}
```
Và ở client, lắng nghe `game_state` event sau khi hiển thị game screen (logic hiện tại đã có `s.on('game_state', ...)` nên chỉ cần server broadcast đúng lúc).

> **Ghi chú:** `handlePlayerReconnect` ở L1421-1447 đã gọi `broadcastState()`. Nhưng nó được gọi ở RoomManager.js L156-157, SAU khi `room_joined` được emit (L149-152). Đây là đúng thứ tự. Vấn đề là client chưa show game screen TRƯỚC khi nhận `game_state`. Cần đảm bảo `UI.showGame()` xảy ra trước khi `game_state` event được process.

### BUG-005 🟡 HIGH — Fake socket object → Socket.io room channel leak

**File:** `server/RoomManager.js`  
**Dòng:** 391–396  

**Root cause:**
```js
this.leaveRoom({ id: socket.id, leave: () => {} });
// leaveRoom() gọi socket.leave(code) ở L226
// fake object: leave() là noop → Socket.io room subscription còn nguyên
```

**Trigger:** Người chơi disconnect nhưng không reconnect trong 60 giây.

**Impact:** Socket thật (nếu vẫn còn connected ở layer dưới) vẫn nhận events của phòng sau khi đã "bị xóa" khỏi game state. Trong thực tế, socket đã disconnect nên impact thấp hơn — nhưng nếu socket reconnect với ID cũ (hiếm), sẽ nhận events ghost.

**Fix direction:**
```js
const timeout = setTimeout(() => {
  this.reconnectTimeouts.delete(socket.id);
  const currentRoom = this.rooms.get(code);
  if (currentRoom) {
    // Tạo một fake-socket với đầy đủ leave behavior
    const fakeSocket = {
      id: socket.id,
      leave: (roomCode) => {
        // Socket đã disconnect, không cần gọi gì
      }
    };
    this.leaveRoom(fakeSocket);
  }
}, 60000);
```
Hoặc tốt hơn: tách logic xử lý room ra khỏi socket.leave().

### BUG-006 🟡 MEDIUM — Attack trong khi đang bị Attack: `turnsToPlay` sai

**File:** `server/ServerGame.js`  
**Dòng:** 910–935  

**Root cause:**
```js
case CardType.ATTACK: {
  const remainingTurns = player.turnsToPlay; // ← lấy trước khi giảm
  nextPlayer.turnsToPlay = remainingTurns + 1;
  // ...
  player.turnsToPlay = 1; // ← reset thủ công, không giảm
  this.currentPlayerIndex = nextIdx;
  this.startTurn();
}
```

**Vấn đề:** Khi player A bị Attack (turnsToPlay=2) và trong lượt đó A đánh Attack lại:
- `remainingTurns = 2`
- `nextPlayer.turnsToPlay = 2 + 1 = 3`

Theo luật Exploding Kittens chuẩn: nếu A đang bị 2 lượt và A dùng Attack, nextPlayer chỉ nhận thêm 2 lượt (không phải 3). Công thức đúng là `nextPlayer.turnsToPlay = remainingTurns` (truyền toàn bộ gánh nặng) — mỗi luật version có thể khác nhau. Cần xác nhận luật muốn áp dụng.

**Trigger:** Attack trong khi đang bị Attack (turnsToPlay > 1).

**Impact:** Sai số lượt chơi — nhẹ nhưng ảnh hưởng cân bằng game.

**Fix direction:**
Xác định luật muốn áp dụng:
- **Option A** (stack): `nextPlayer.turnsToPlay = remainingTurns + 2` (mỗi Attack thêm 2)
- **Option B** (transfer): `nextPlayer.turnsToPlay = remainingTurns` (chuyển giao toàn bộ)

### BUG-008 🟡 MEDIUM — Nope đánh đơn: discard state không nhất quán khi trả lại bài

**File:** `server/ServerGame.js`  
**Dòng:** 466–473  

**Root cause:**
```js
if (card.type === CardType.NOPE) {
  this.emitTo(playerId, 'error_message', { message: 'Không có gì để Phản Đối!' });
  // Trả lại bài
  this.discardPile.pop(); // ← xóa khỏi discard
  player.hand.push(card); // ← trả về tay
  return;
}
```
Trước đó (L456-457), card đã được remove khỏi hand và push vào discardPile. Việc `.pop()` giả định Nope là lá cuối cùng trong discardPile — điều này đúng nếu không có side effect. Tuy nhiên `card_played` event đã được emit ở L476-482 TRƯỚC khi check Nope — **nhưng thực ra Nope check xảy ra TRƯỚC `card_played` emit** (L466 < L476). Okay, thứ tự đúng. Tuy nhiên `.pop()` không safe nếu có concurrent call dù Node.js single-threaded.

**Thực tế:** Đây là safe nhưng **logic trả bài Nope này sẽ không bao giờ được gọi** vì Nope là action card riêng biệt (chỉ dùng qua `handleNopeResponse`), không bao giờ bị đánh đơn qua `handlePlayCards` — trừ khi người dùng cố tình gửi event `play_cards` với Nope. Server chặn đúng.

**Re-assessment:** BUG-008 → **Low, edge case không ảnh hưởng thực tế**.

### BUG-010 🟢 LOW — `turn_start` client: lookup players theo currentPlayerIndex sai

**File:** `public/js/network.js`  
**Dòng:** 312  

**Root cause:**
```js
const isMyTurn = Game.players[data.currentPlayerIndex]?.id === this.myPlayerId;
```
`Game.players` là mảng được map từ server state — **index trong mảng không đảm bảo bằng `player.index`**. Nếu một người chơi bị loại và mảng bị reorder, `data.currentPlayerIndex = 2` không nhất thiết là `Game.players[2]`.

**Trigger:** Sau khi có người bị loại, thứ tự players trong client array có thể lệch.

**Impact:** Client nhận nhầm lượt → UI không enable/disable đúng action buttons.

**Fix direction:**
```js
const isMyTurn = Game.players.find(p => p.index === data.currentPlayerIndex)?.id === this.myPlayerId;
```
